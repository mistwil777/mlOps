1. Pourquoi le Green IT avec un LLM 🌱 Débutant

Les bases conceptuelles — comprendre ce qui coûte avant de configurer

Définition — Green IT

Ensemble de pratiques visant à réduire l'empreinte environnementale du numérique : énergie, CO₂, réseau, mémoire. Avec un LLM, l'unité de mesure principale est le token — chaque token traité consomme du GPU dans un datacenter distant.

⚡

1 token ≈ 0,75 mot ≈ énergie

Un prompt de 10 000 tokens consomme ~10× plus d'énergie qu'un prompt de 1 000 tokens. Multiplié par des milliers d'appels quotidiens, l'impact est réel et mesurable.

🔁

Répétition = gaspillage

Faire relire un fichier de 800 lignes à chaque échange pour en extraire 3 valeurs, alors qu'une requête SQL suffirait — c'est l'anti-pattern n°1.

🏠

Local = souverain + green

Inférence locale : zéro transit réseau, zéro cloud, zéro CO₂ datacenter distant. Obligatoire pour les projets avec contraintes de souveraineté ou de confidentialité.

🎯

IA là où elle apporte de la valeur

Tout ce qu'un outil classique fait mieux (SQL, grep, jq) doit être délégué à cet outil. Le LLM n'intervient que pour le raisonnement symbolique à valeur ajoutée.

2. Architecture de configuration Claude Code 🌱 Débutant

Les fichiers qui gouvernent le comportement de l'agent

Définition — Claude Code (CC)

CLI officiel d'Anthropic. Agit directement sur votre système (fichiers, shell, APIs). Entièrement configurable via fichiers JSON et Markdown. Deux niveaux : global (~/.claude/) et projet (.claude/ dans le repo).

3. CLAUDE.md — instructions permanentes 🌱 Débutant

Le fichier le plus impactant sur la qualité et le coût des échanges

Définition — CLAUDE.md

Fichier Markdown lu automatiquement à chaque session. C'est le "contrat" entre vous et l'agent : contexte projet, chemins, règles métier, format de réponse. Une fois bien rédigé, vous ne répétez plus jamais le contexte dans chaque prompt.

Structure optimale — section Token Economy indispensable

CLAUDE.md## Token Economy — CC Rules   ← SECTION CRITIQUE GREEN IT
- Tâches répétitives (scoring, validation) → Agent subtype haiku
- Exploration codebase → Agent subtype Explore
- Fichiers >300 lignes → demander résumé avant lecture complète
- Requêtes métadonnées → MCP sqlite, jamais lecture fichier .db
- /compact après >30 échanges dans la session
- Prefer short + precise questions over long explanations

❌ CLAUDE.md avec données dynamiques

Inclure des timestamps, IDs de run ou compteurs invalide le prompt cache à chaque session. Zéro économie cache.

✅ CLAUDE.md 100% statique

Uniquement des faits stables : chemins, stack, règles. Les données dynamiques passent dans le prompt, pas dans le contexte permanent.

5. Permissions — Allowlist & Deny list 🌿 Intermédiaire

Contrôle précis des actions — zéro prompt inutile, zéro risque accidentel

Définition — Allowlist / Deny list

L'allowlist liste les commandes que CC peut exécuter sans confirmation. La deny list interdit des opérations spécifiques même si elles seraient normalement permises. La deny list a la priorité absolue sur l'allowlist.

Exemple complet — projet générique

.claude/settings.json{
  "permissions": {
    "allow": [
      "Bash(python *.py)",
      "Bash(git log*)", "Bash(git diff*)", "Bash(git add *)",
      "Bash(ls *)", "Bash(grep -r *)", "Bash(pytest *)",
      "Write(~/your-project/src/**)",
      "Write(~/your-project/tests/**)"
    ],
    "deny": [
      "Write(~/your-project/data/raw/**)",  // données sources = IMMUTABLES
      "Bash(curl * openai*)",               // souveraineté
      "Bash(rm -rf *)",
      "Bash(git push --force*)"
    ]
  }
}
💡
Skill /fewer-permission-prompts Scanne vos transcripts pour les appels Bash répétitifs et ajoute automatiquement les entrées allowlist manquantes dans .claude/settings.json. À lancer après une semaine d'utilisation.

6. Hooks — audit & automatisation 🌿 Intermédiaire

Commandes déclenchées automatiquement autour de chaque outil

Définition — Hook

Commande shell qui se déclenche avant (PreToolUse) ou après (PostToolUse) l'utilisation d'un outil, ou à la fin de la session (Stop). Claude ne voit pas les hooks — ce sont des effets de bord du harness d'exécution.

🔍

PreToolUse

S'exécute avant l'outil. Peut bloquer l'exécution (code retour ≠ 0). Utile pour validation, double-check avant suppression, vérification de périmètre.

📝

PostToolUse

S'exécute après l'outil. Idéal pour audit, métriques, notification. Ne peut pas annuler l'action déjà effectuée.

🏁

Stop

Déclenché quand Claude termine sa réponse. Pour rapport de session, marqueur dans audit.log, notification équipe.

Hook d'audit robuste — avec jq

❌ Naïf — entrées vides

echo "$(date) | $CLAUDE_TOOL_INPUT" >> audit.log
# CLAUDE_TOOL_INPUT = JSON multi-lignes
# → echo échoue silencieusement

✅ Robuste — jq extrait le champ

printf '%s | BASH | %s\n' \
  "$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
  "$(echo "$CLAUDE_TOOL_INPUT" | \
     jq -r '.command // empty' 2>/dev/null)" \
  >> .claude/audit.log

7. Skills — réutilisation & spécialisation 🌿 Intermédiaire

Les commandes /slash qui encapsulent de la logique complexe et réduisent les tokens répétés

Définition — Skill

Un skill est un fichier Markdown (.md) placé dans ~/.claude/skills/ (global) ou .claude/skills/ (projet). Il est invoqué par /nom-du-skill et contient des instructions précises, des exemples et des séquences d'actions. C'est l'équivalent d'une "macro" intelligente pour Claude Code.

♻️

Zéro répétition de contexte

Sans skill, chaque appel réexplique les paramètres, les chemins, les règles. Avec un skill, tout est encapsulé une fois pour toutes.

🎯

Prompt ultra-ciblé

Un skill bien écrit contient exactement le contexte nécessaire — ni plus, ni moins. Il ne charge pas tout le CLAUDE.md général dans le contexte de la tâche.

🔗

Orchestration multi-étapes

Un skill peut enchaîner : nettoyage → validation → traitement → déploiement. L'utilisateur tape une commande, pas 20 prompts.

🧩

Partage d'équipe

Les skills dans .claude/skills/ sont versionnés avec le repo — toute l'équipe dispose des mêmes recettes, sans réinventer à chaque fois.

Structure d'un skill

~/.claude/skills/process-dataset.md# /process-dataset — Traite un dataset avec validation et rapport

## Déclencheur
Invoqué par : `/process-dataset [nom]`

## Contexte injecté automatiquement
- Input : data/processed/[nom]/
- Output : data/fine-tuning-ready/[nom]/train.jsonl
- Format attendu : JSONL avec champs instruction/output

## Séquence d'actions
1. Vérifier que le dataset existe (wc -l, validation format)
2. Lancer le pipeline de nettoyage
3. Logger les métriques qualité
4. Afficher un résumé

## Token Economy
- Utiliser Agent subtype haiku pour la validation ligne par ligne
- Ne pas relire les fichiers de config déjà chargés
💡
Règle de création d'un skill Si vous tapez la même séquence de prompts plus de 3 fois, c'est un skill. Si vous expliquez le même contexte à chaque session, c'est du CLAUDE.md. Le skill contient de la logique d'action ; CLAUDE.md contient du contexte statique.

8. Agents & Sub-agents 🌳 Expert

Délégation intelligente — le levier le plus puissant pour la qualité ET la performance

Définition — Agent / Sub-agent

Un agent est une instance de Claude qui reçoit une tâche, dispose de ses propres outils, et renvoie un résultat. Un sub-agent est lancé par l'outil Agent() depuis le contexte principal. Ils permettent la parallélisation, la spécialisation par modèle, et la protection du contexte principal (résultats volumineux restent dans le sub-agent).

Types d'agents disponibles dans CC

TypeSpécialisationModèle optimalUsage Green IT
ExploreExploration codebase (glob, grep, read)HaikuNe surcharge pas le contexte principal avec des résultats de recherche
general-purposeCatch-all, recherche multi-étapes, tâches complexesSonnetParalléliser des recherches indépendantes
PlanConception d'architecture, plans d'implémentationOpusRéservé aux décisions structurantes — coûteux mais rare
claude-apiIntégration SDK Anthropic, prompt caching, tool useSonnetTâches API sans polluer le contexte principal
claude-code-guideQuestions sur CC (CLI, hooks, MCP, SDK, keybindings)SonnetDécharge le contexte principal pour les questions de config
code-reviewerRevue de code, bugs, sécurité, refactoringSonnetRevue indépendante sans biaiser le contexte principal
deep-researchRecherche web multi-sources, vérification adversarialeOpusRapports factuels cités — coûteux, réserver aux recherches importantes

Exemple — scoring de dataset en parallèle

// Déléguer le scoring répétitif à Haiku en parallèle
Agent({
  subagent_type: "general-purpose",
  model: "haiku",        // ← override modèle → ×15 moins cher qu'Opus
  prompt: "Score each pair in data/processed/batch_042.jsonl on 0-10...",
  run_in_background: true  // ← non-bloquant
})
✅
Pattern optimal : contexte principal Sonnet, sous-tâches Haiku Le contexte principal orchestre (Sonnet/Opus), les tâches répétitives ou d'exploration sont déléguées à des sub-agents Haiku. Le ratio coût/qualité est optimal. Seuls les résultats synthétisés remontent — jamais les données brutes volumineuses.
⚠️
Ne pas paralléliser des tâches dépendantes Si la tâche B utilise les résultats de la tâche A, elles doivent être séquentielles. La parallélisation n'est valide que pour des tâches vraiment indépendantes.

9. Workflow — orchestration déterministe 🌳 Expert

Scripts JS qui pilotent des dizaines d'agents en parallèle, avec reprise sur incident

Définition — Workflow

Un Workflow est un script JavaScript qui orchestre plusieurs sub-agents de façon déterministe — via du code, pas du raisonnement LLM. Il permet le fan-out (parallélisme réel), la pipeline multi-étapes, et la résumabilité : si interrompu, les agents déjà complétés retournent leur résultat depuis le cache.

Agent() simple

Une seule instance. Parallélisme possible mais non garanti. Pas de reprise sur incident. Logique de branchement laissée au LLM.

Workflow

Dizaines d'agents concurrents. Fan-out déterministe (code). resumeFromRunId : reprise gratuite des agents déjà complétés. Jusqu'à 16 agents simultanés, 1000 agents max par workflow.

Fonctions clés

FonctionComportementQuand l'utiliser
agent(prompt, opts)Lance un sub-agent, retourne son résultat (texte ou objet JSON si schema)Toujours — brique de base
pipeline(items, ...stages)Chaque item traverse les stages sans barrière — item A peut être en stage 3 pendant que B est en stage 1Défaut — wall-clock = chaîne la plus lente
parallel(thunks)Barrière : attend TOUS les thunks avant de continuerSeulement si le stage N a besoin de TOUS les résultats du stage N-1
phase(title)Groupe les agents suivants sous un titre dans l'UIChaque étape logique (Scan, Review, Fix…)
log(message)Affiche un message de progression à l'utilisateurBoucles longues, état d'avancement
⚠️
pipeline() par défaut, parallel() seulement si nécessaire Une barrière parallel() bloque tous les items jusqu'au plus lent. N'utiliser que si le stage suivant a besoin de la totalité des résultats (ex : déduplication cross-items). Pour tout le reste : pipeline().

Exemple — scoring de dataset en fan-out

.claude/workflows/score-dataset.jsexport const meta = {
  name: 'score-dataset',
  description: 'Score all pairs in a dataset in parallel with Haiku',
  phases: [
    { title: 'Load', detail: 'read JSONL and split into batches' },
    { title: 'Score', detail: 'parallel Haiku scoring' },
  ],
}

const SCORE_SCHEMA = {
  type: 'object',
  properties: {
    score: { type: 'number' },
    reason: { type: 'string' }
  }
}

phase('Load')
const batches = await agent(
  'Read data/processed/current/train.jsonl and split into batches of 50. Return array of batch file paths.',
  { schema: { type: 'object', properties: { paths: { type: 'array', items: { type: 'string' } } } } }
)

phase('Score')
const results = await pipeline(
  batches.paths,
  path => agent(
    `Score each pair in ${path} on 0-10 for quality. Return scores array.`,
    { model: 'haiku', label: `score:${path}`, phase: 'Score' }
  )
)

log(`Scored ${results.flat().length} pairs`)
return results.flat()

Résumabilité — Green IT pour les longs workflows

✅
Reprise gratuite avec resumeFromRunId Si un workflow de 200 agents est interrompu après 150 agents, relancer avec resumeFromRunId retourne les 150 résultats depuis le cache instantanément. Seuls les 50 agents restants sont réexécutés. Zéro retokenisation des agents déjà complétés.

10. MCP Servers — outils précis 🌳 Expert

Model Context Protocol — donner à Claude des outils chirurgicaux au lieu de lui faire relire des fichiers entiers

Définition — MCP (Model Context Protocol)

Protocole open-source d'Anthropic pour connecter des LLMs à des sources de données et outils externes. Un MCP Server expose des outils appelables directement : execute_query sur SQLite, read_file ciblé, search vectoriel. C'est l'alternative Green IT à "colle tout le fichier dans le contexte".

❌ Sans MCP — ~3 500 tokens

Claude tente de lire une DB binaire (illisible), exporte un CSV de 800 lignes, relit le CSV complet pour trouver les 3 dernières entrées. 3 500 tokens gaspillés.

✅ Avec MCP SQLite — ~180 tokens

execute_query("SELECT * FROM runs ORDER BY start_time DESC LIMIT 3") → 3 lignes → 180 tokens. Gain : ×20.

MCP Servers essentiels

🗄️

mcp-server-sqlite

Requêtes SQL directes sur n'importe quelle DB SQLite (métadonnées, logs, expériences). Installation : uvx mcp-server-sqlite

📂

mcp-server-filesystem

Accès fichiers précis : liste, lecture partielle, recherche. Plus ciblé que ls + cat enchaînés. Évite de charger des arborescences complètes.

🔎

mcp-server-qdrant

Recherche sémantique dans la base vectorielle. Interroger les entrées similaires sans les charger toutes en contexte.

🌐

mcp-server-brave-search

Veille tech (nouveaux modèles, papers, CVE) directement depuis CC. Résultats directement dans le contexte, pas de navigateur.

Configuration globale (Green IT : partagée entre projets)

~/.claude/settings.json{
  "mcpServers": {
    "sqlite": {
      "command": "uvx",
      "args": ["mcp-server-sqlite", "--db-path",
               "~/your-project/data/db.sqlite"]
    },
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem",
               "~/your-project"]
    }
  }
}
💡
MCP dans les Workflows Les agents lancés par Workflow ont accès à tous les MCP servers via ToolSearch — les schemas sont chargés à la demande par agent. Un workflow de 50 agents peut tous interroger SQLite sans configuration supplémentaire.
💡
Règle MCP Green IT Toute question "quelle est la dernière entrée avec score < 0.5 ?" doit passer par MCP SQLite. Toute lecture partielle de fichier par MCP filesystem. Le LLM n'est pas un système de fichiers.

11. Prompt Cache & Batch API 🌳 Expert

Les mécanismes invisibles qui réduisent les coûts de 50 à 90%

Prompt Cache — économie automatique si CLAUDE.md est stable

Définition — Prompt Cache

Claude met en cache les préfixes de prompts identiques pendant 5 minutes. Si votre CLAUDE.md + contexte système restent stables entre deux échanges, seule la partie nouvelle est traitée. Les tokens en cache sont facturés ~90% moins cher et consomment proportionnellement moins d'énergie.

Batch API — traitement asynchrone de masse

Définition — Batch API

L'API Batch d'Anthropic permet d'envoyer des milliers de requêtes en une seule fois, traitées de manière asynchrone. Coût : 50% moins cher que l'API standard, avec un délai de quelques heures. Idéal pour le nettoyage et le scoring de datasets volumineux.

📦

Cas d'usage parfait

Scorer 50 000 entrées avec Haiku via Batch API : ×50% de réduction de coût, lancé le soir, résultats le matin. Zéro coût d'attente humain.

⏱️

Quand l'utiliser

Tâches non-interactives : scoring dataset, évaluation sur test set, génération d'augmentations synthétiques. Pas pour les interactions utilisateur en temps réel.

from anthropic import Anthropic
from pathlib import Path
import json

client = Anthropic()

def score_items_batch(items_path: Path) -> str:
    items = [json.loads(l) for l in items_path.read_text().splitlines()]
    requests = [{
        "custom_id": f"item-{i}",
        "params": {
            "model": "claude-haiku-4-5-20251001",  # haiku = ×15 moins cher
            "max_tokens": 64,
            "messages": [{"role": "user", "content": f"Score 0-10: {item}"}]
        }
    } for i, item in enumerate(items)]
    batch = client.messages.batches.create(requests=requests)
    return batch.id  # résultats disponibles dans quelques heures

12. Sécurité & Souveraineté 🌳 Expert

Secrets hors settings.json, deny cloud, données sources immutables

🔴
Clés en clair dans settings.json = vulnérabilité critique Ce fichier est lisible par tout processus tournant sous votre utilisateur. Utiliser ~/.aws/credentials (chmod 600) + profil nommé dans settings.json.

❌ Secrets dans settings.json

{
  "env": {
    "AWS_ACCESS_KEY_ID": "AKIA...",     // ← DANGER
    "AWS_SECRET_ACCESS_KEY": "abc..."   // ← DANGER
  }
}

✅ Profil AWS standard

# ~/.aws/credentials (chmod 600)
[my-project]
aws_access_key_id = AKIA...
aws_secret_access_key = abc...

# settings.json — juste le profil
{ "env": { "AWS_PROFILE": "my-project" } }

Deny list souveraineté — projets avec contraintes de confidentialité

"deny": [
  "Bash(curl * openai*)",       // pas d'appel cloud sortant
  "Bash(curl * anthropic*)",    // inférence locale uniquement
  "Bash(wget * s3*)",
  "Write(~/your-project/data/raw/**)"  // données sources = IMMUTABLES
]
Définition — Immutabilité de la couche raw

La couche raw/ contient les données sources non transformées. Elle ne doit jamais être modifiée après ingestion — c'est la source de vérité pour rejouer le pipeline. La deny Write dans settings.json en fait une règle technique non-contournable, pas juste une convention.

🌱 Fondamentaux
Qu'est-ce qu'un token, et pourquoi est-il l'unité de mesure Green IT d'un LLM ?
↩ cliquer pour la réponse
Un token ≈ 0,75 mot (4 caractères). C'est l'unité de calcul GPU : chaque token consomme de l'énergie dans un datacenter. 1 fichier source de 300 lignes ≈ 3 000 tokens. Multiplié par des milliers d'appels/jour, l'impact CO₂ est mesurable et réductible par la configuration.
↩ retourner
Quelle est la différence entre ~/.claude/settings.json et .claude/settings.json ?
↩ cliquer pour la réponse
Global (~/.claude/) : s'applique à tous les projets — modèles, MCP servers, env vars partagées. Projet (.claude/) : versionné dans le repo, contient permissions, hooks, deny list spécifiques. Le projet surcharge le global.
↩ retourner
Pourquoi le CLAUDE.md doit-il être 100% statique (sans timestamps ni IDs dynamiques) ?
↩ cliquer pour la réponse
Le prompt cache d'Anthropic met en cache les préfixes identiques pendant 5 min. Si CLAUDE.md change à chaque session, le cache est invalidé → 100% des tokens sont refacturés. Un CLAUDE.md statique permet un cache hit rate de 90%+.

Quel est le rôle de la section "Token Economy" dans CLAUDE.md ?
↩ cliquer pour la réponse
Elle instruite Claude sur comment utiliser ses propres ressources : quel modèle pour quelle tâche, quand déléguer à un sub-agent Haiku, quand utiliser MCP au lieu de lire un fichier, quand faire /compact. Sans elle, Claude peut consommer ×10 plus de tokens par manque d'instructions explicites.

🌿 Permissions & Hooks
Quelle est la différence entre allowlist et deny list, et laquelle a la priorité ?
↩ cliquer pour la réponse
Allowlist : commandes que CC exécute sans confirmation. Deny list : commandes explicitement interdites même si elles seraient normalement permises. La deny list a la priorité absolue — si une commande est dans les deux, elle est bloquée.
↩ retourner
Que signifie Bash(git log*) comme règle d'allowlist ?
↩ cliquer pour la réponse
Autorise toute commande qui commence exactement par git log : git log --oneline -10 ✓, git log --format="%H" ✓.
N'autorise pas : git push ✗, git reset --hard ✗. Le * est un glob suffixe, pas un wildcard global.

Quelle est la différence entre PreToolUse, PostToolUse et Stop ?
↩ cliquer pour la réponse
PreToolUse : avant l'outil, peut bloquer (code ≠ 0). Ex : valider qu'un fichier à écrire n'est pas dans raw/.
PostToolUse : après l'outil, pour l'audit. Ex : logger la commande Bash dans audit.log.
Stop : fin de réponse Claude. Ex : marqueur === session end ===.

🌳 Agents, Workflows & MCP
Qu'est-ce qu'un skill Claude Code, différent d'une entrée CLAUDE.md ?
↩ cliquer pour la réponse
Un skill est un fichier .md dans .claude/skills/, invoqué par /nom. Il contient de la logique d'action : séquence d'étapes, règles spécifiques à une tâche.
CLAUDE.md contient du contexte statique : chemins, stack, règles permanentes. Skill = macro réutilisable ; CLAUDE.md = contrat permanent.
↩ retourner
Quelle est la différence entre pipeline() et parallel() dans un Workflow ?
↩ cliquer pour la réponse
pipeline() : pas de barrière — chaque item avance dans les stages indépendamment. Wall-clock = chaîne la plus lente d'un seul item. Défaut à utiliser.
parallel() : barrière — attend TOUS les résultats avant de continuer. À réserver aux cas où le stage suivant a besoin de la totalité des résultats précédents.
↩ retourner
Qu'apporte la résumabilité (resumeFromRunId) d'un Workflow ?
↩ cliquer pour la réponse
Si un workflow de 200 agents est interrompu après 150, relancer avec resumeFromRunId retourne les 150 résultats depuis le cache instantanément — zéro retokenisation. Seuls les 50 agents restants sont réexécutés. Essentiel pour les long-running workflows coûteux.
↩ retourner
Pourquoi utiliser MCP SQLite au lieu de lire une DB directement ? Chiffrez le gain.
↩ cliquer pour la réponse
Sans MCP : CC tente de lire le binaire (illisible), exporte un CSV de 800 lignes, le charge entier → ~3 500 tokens.
Avec MCP : execute_query("SELECT ... LIMIT 3") → 3 lignes → ~180 tokens.
Gain : ×20. Le LLM n'est pas un système de fichiers.
↩ retourner
Le prompt cache d'Anthropic dure combien de temps ? Quelles pratiques le maximisent ?
↩ cliquer pour la réponse
TTL : 5 minutes. Pour maximiser le hit rate : ① CLAUDE.md 100% statique. ② Enchaîner les échanges en moins de 5 min. ③ Utiliser /compact qui résume sans changer le préfixe stable. Les tokens en cache sont facturés ~90% moins cher.
↩ retourner
Pourquoi ne jamais mettre des clés d'API dans settings.json ?
↩ cliquer pour la réponse
settings.json est lisible par tout processus tournant sous votre utilisateur. Contrairement à ~/.aws/credentials (chmod 600), il n'a pas de permission spéciale. Alternative : credentials provider standard + "AWS_PROFILE": "mon-profil" dans settings.
↩ retourner

15. Checklist & Anti-patterns 🌿 Intermédiaire

🌱 Débutant — fondations

  • CLAUDE.md avec contexte, chemins, règles
  • Section Token Economy dans CLAUDE.md
  • "model": "haiku" dans settings global
  • Variables ANTHROPIC_MODEL (Sonnet) + SMALL_FAST (Haiku) + LARGE (Opus)

🌿 Intermédiaire

  • Allowlist minimale pour le travail courant
  • Deny list souveraineté + données sources immutables
  • Secrets d'API hors settings.json
  • Hook PostToolUse audit avec jq
  • Hook Stop avec marqueur de fin de session
  • Au moins 3 skills versionnés dans .claude/skills/
  • Mémoire persistante initialisée (MEMORY.md)

🌳 Expert

  • MCP SQLite pour toutes les requêtes métadonnées
  • MCP Filesystem configuré
  • Sub-agents Haiku pour tâches répétitives
  • Au moins 1 Workflow défini pour les tâches fan-out
  • Batch API pour datasets volumineux (>500 entrées)
  • Cache hit rate mesuré et >60%
  • Fast mode configuré pour sessions interactives intenses
  • Rapport hebdomadaire sur audit.log
  • Dashboard de consommation tokens
  • Rotation automatique des credentials

🚫 Anti-patterns critiques

Clés secrets dans settings.json

Lisibles par tout process. Utiliser le credentials provider standard (chmod 600).

Bash(*) — tout autoriser

Autorise rm -rf /. La friction des prompts est un signal — affiner l'allowlist.

CLAUDE.md avec données dynamiques

Timestamps ou IDs → cache invalidé à chaque session. Zéro économie.

Opus/Sonnet pour tout "par sécurité"

×5 à ×15 le coût. Haiku couvre 60–70% des tâches courantes.

Lire une DB SQLite comme fichier

Binaire illisible → CSV 800 lignes → 3 500 tokens. MCP SQLite : 180 tokens.

parallel() au lieu de pipeline()

Barrière inutile → le plus lent bloque tout. pipeline() par défaut, parallel() seulement si nécessaire.

Sessions sans /compact

Après 30 échanges, le contexte est redondant. /compact libère la fenêtre.
