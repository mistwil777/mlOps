1. Pourquoi le Green IT avec un LLM 🌱 Débutant

Les bases conceptuelles — comprendre ce qui coûte avant de configurer

Définition — Green IT

Ensemble de pratiques visant à réduire l'empreinte environnementale du numérique : énergie, CO₂, réseau, mémoire. Avec un LLM, l'unité de mesure principale est le token — chaque token traité consomme du GPU dans un datacenter.

⚡

1 token ≈ 0,75 mot ≈ énergie

Un prompt de 10 000 tokens consomme ~10× plus d'énergie qu'un prompt de 1 000 tokens. Multiplié par des milliers d'appels quotidiens, l'impact est réel.

🔁

Répétition = gaspillage

Faire relire un fichier de 800 lignes à chaque échange pour en extraire 3 valeurs, alors qu'une requête SQL suffirait — c'est l'anti-pattern n°1.

🏠

Local = souverain + green

Inférence locale (mlx_lm.server) : zéro transit réseau, zéro cloud, zéro CO₂ datacenter distant. Obligatoire pour les projets defense/classifiés.

🎯

IA là où elle apporte de la valeur

Tout ce qu'un outil classique fait mieux (SQL, grep, jq) doit être délégué à cet outil. Le LLM n'intervient que pour le raisonnement symbolique.

2. Architecture de configuration Claude Code 🌱 Débutant

Les fichiers qui gouvernent le comportement de l'agent

Définition — Claude Code (CC)

CLI officiel d'Anthropic. Agit directement sur votre système (fichiers, shell, APIs). Entièrement configurable via fichiers JSON et Markdown. Deux niveaux : global (~/.claude/) et projet (.claude/ dans le repo).

3. CLAUDE.md — instructions permanentes 🌱 Débutant

Le fichier le plus impactant sur la qualité et le coût des échanges

Définition — CLAUDE.md

Fichier Markdown lu automatiquement à chaque session. C'est le "contrat" entre vous et l'agent : contexte projet, chemins, règles métier, format de réponse. Une fois bien rédigé, vous ne répétez plus jamais le contexte dans chaque prompt.

Structure optimale — section Token Economy indispensable

CLAUDE.md## Token Economy — CC Rules   ← SECTION CRITIQUE GREEN IT
- Tâches répétitives (scoring) → Agent subtype haiku
- Exploration codebase → Agent subtype Explore
- Fichiers >300 lignes → demander résumé avant lecture complète
- Requêtes métadonnées → MCP sqlite, jamais lecture fichier .db
- /compact après >30 échanges dans la session
- Prefer short + precise questions over long explanations

❌ CLAUDE.md avec données dynamiques

Inclure des timestamps, IDs de run ou compteurs invalide le prompt cache à chaque session. Zéro économie cache.

✅ CLAUDE.md 100% statique

Uniquement des faits stables : chemins, stack, règles. Les données dynamiques passent dans le prompt, pas dans le contexte permanent.

5. Permissions — Allowlist & Deny list 🌿 Intermédiaire

Contrôle précis des actions — zéro prompt inutile, zéro risque accidentel

Définition — Allowlist / Deny list

L'allowlist liste les commandes que CC peut exécuter sans confirmation. La deny list interdit des opérations spécifiques même si elles seraient normalement permises. Ensemble, elles définissent la surface d'action de l'agent.

Exemple complet — projet MLOps

.claude/settings.json{
  "permissions": {
    "allow": [
      "Bash(mlx_lm.*)",        // fine-tuning local
      "Bash(python *.py)",
      "Bash(dvc *)",           // versioning données
      "Bash(git log*)", "Bash(git diff*)", "Bash(git add *)",
      "Bash(ollama *)", "Bash(mlflow *)",
      "Bash(ls *)", "Bash(grep -r *)", "Bash(pytest *)",
      "Write(~/mlOps/datalake/processed/**)",
      "Write(~/mlOps/experiments/**)"
    ],
    "deny": [
      "Write(~/mlOps/datalake/raw/**)",  // raw IMMUTABLE
      "Bash(curl * anthropic*)",          // souveraineté
      "Bash(curl * openai*)",
      "Bash(rm -rf *)",
      "Write(~/migrator/**)"              // repo tiers = read-only
    ]
  }
}

6. Hooks — audit & automatisation 🌿 Intermédiaire

Commandes déclenchées automatiquement autour de chaque outil

Définition — Hook

Commande shell qui se déclenche avant (PreToolUse) ou après (PostToolUse) l'utilisation d'un outil, ou à la fin de la session (Stop). Claude ne voit pas les hooks — ce sont des effets de bord du harness d'exécution.

🔍

PreToolUse

S'exécute avant l'outil. Peut bloquer l'exécution (code retour ≠ 0). Utile pour validation, double-check avant suppression.

📝

PostToolUse

S'exécute après l'outil. Idéal pour audit, métriques, notification. Ne peut pas annuler l'action.

🏁

Stop

Déclenché quand Claude termine sa réponse. Pour rapport de session, marqueur dans audit.log, notification équipe.

Hook d'audit robuste — avec jq

❌ Naïf — entrées vides

echo "$(date) | $CLAUDE_TOOL_INPUT" >> audit.log
# CLAUDE_TOOL_INPUT = JSON multi-lignes
# → echo échoue silencieusement

✅ Robuste — jq extrait le champ

printf '%s | BASH | %s\n' \
  "$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
  "$(echo "$CLAUDE_TOOL_INPUT" | \
     jq -r '.command // empty' 2>/dev/null)" \
  >> .claude/audit.log

7. Skills — réutilisation & spécialisation 🌿 Intermédiaire

Les commandes /slash qui encapsulent de la logique complexe et réduisent les tokens répétés

Définition — Skill

Un skill est un fichier Markdown (.md) placé dans ~/.claude/skills/ (global) ou .claude/skills/ (projet). Il est invoqué par une commande /nom-du-skill et contient des instructions précises, des exemples, et éventuellement des séquences d'actions. C'est l'équivalent d'une "macro" intelligente pour Claude Code.

Pourquoi les skills sont du Green IT

♻️

Zéro répétition de contexte

Sans skill, chaque appel à "lancer le fine-tuning" réexplique les paramètres optimaux, les chemins, les règles MLflow. Avec un skill, tout est encapsulé une fois.

🎯

Prompt ultra-ciblé

Un skill bien écrit contient exactement le contexte nécessaire — ni plus, ni moins. Il ne charge pas tout le CLAUDE.md général dans le contexte de la tâche.

🔗

Orchestration multi-étapes

Un skill peut enchaîner : nettoyage → validation → fine-tuning → évaluation → deploy. L'utilisateur tape /train-lora, pas 20 prompts.

🧩

Partage d'équipe

Les skills dans .claude/skills/ sont versionnés avec le repo — toute l'équipe dispose des mêmes recettes, sans réinventer à chaque fois.

Structure d'un skill

~/.claude/skills/train-lora.md# /train-lora — Lance le fine-tuning LoRA avec config optimale M4 Pro

## Déclencheur
Invoqué par : `/train-lora [projet]`

## Contexte injecté automatiquement
- Modèle de base : Mistral 7B Instruct 4-bit
- batch_size optimal : 8 (7B 4-bit sur M4 Pro 48GB)
- Dataset : datalake/fine-tuning-ready/[projet]/train.jsonl
- Adapter output : adapters/[projet]/

## Séquence d'actions
1. Vérifier que le dataset existe et est valide (wc -l, vérification special tokens)
2. Lancer mlx_lm.lora avec les paramètres optimaux
3. Logger la run dans MLflow (OBLIGATOIRE)
4. Afficher un résumé val_loss

## Token Economy
- Utiliser Agent subtype haiku pour la validation du dataset
- Ne pas relire les fichiers de config déjà chargés

Règle de création d'un skill Si vous tapez la même séquence de prompts plus de 3 fois, c'est un skill. Si vous expliquez le même contexte à chaque session, c'est du CLAUDE.md. La frontière : le skill contient de la logique d'action, CLAUDE.md contient du contexte statique.

8. Agents & Sub-agents 🌳 Expert

Délégation intelligente — le levier le plus puissant pour la qualité ET la performance

Définition — Agent / Sub-agent

Un agent est une instance de Claude qui reçoit une tâche, dispose de ses propres outils, et renvoie un résultat. Un sub-agent est un agent lancé par Claude depuis le contexte principal via l'outil Agent(). Ils permettent la parallélisation, la spécialisation (type de modèle), et la protection du contexte principal (résultats volumineux restent dans le sub-agent).

Types d'agents disponibles dans CC

TypeSpécialisationModèle optimalUsage Green IT
ExploreExploration codebase (glob, grep, read)HaikuNe surcharge pas le contexte principal avec des résultats de recherche
general-purposeRecherche multi-étapes, tâches complexesSonnetParalléliser des recherches indépendantes
PlanConception d'architecture, plans d'implémentationOpusRéservé aux décisions structurantes — coûteux mais rare
claude-apiIntégration API Anthropic, SDKSonnetTâches spécifiques API sans polluer le contexte principal
claude-code-guideQuestions sur CC (CLI, hooks, MCP)SonnetDécharge le contexte principal pour les questions de config

Exemple concret — scoring de 5 000 paires

// Dans un skill /clean-dataset :
// Déléguer le scoring répétitif à Haiku en parallèle

Agent({
  subagent_type: "general-purpose",
  model: "haiku",        // ← override modèle → ×15 moins cher qu'Opus
  prompt: "Score each pair in datalake/processed/batch_042.jsonl...",
  run_in_background: true  // ← non-bloquant
})
✅
Pattern optimal : contexte principal Sonnet, sous-tâches Haiku Le contexte principal orchestre (Sonnet/Opus), les tâches répétitives ou d'exploration sont déléguées à des sub-agents Haiku. Le ratio coût/qualité est optimal.

Background agents — parallélisme réel

Avec run_in_background: true, plusieurs agents s'exécutent simultanément. Exemple : lancer en parallèle l'évaluation sur le dataset de validation ET la génération du rapport MLflow, au lieu de les exécuter séquentiellement.

⚠️
Ne pas paralléliser des tâches dépendantes Si la tâche B utilise les résultats de la tâche A, elles doivent être séquentielles. La parallélisation n'est valide que pour des tâches vraiment indépendantes.

9. MCP Servers — outils précis 🌳 Expert

Model Context Protocol — donner à Claude des outils chirurgicaux au lieu de lui faire relire des fichiers entiers

Définition — MCP (Model Context Protocol)

Protocole open-source d'Anthropic pour connecter des LLMs à des sources de données et outils externes. Un MCP Server expose des "outils" appelables directement : execute_query sur SQLite, read_file sur un répertoire, search sur une base vectorielle. C'est l'alternative Green IT à "colle tout le fichier dans le contexte".

❌ Sans MCP — ~3 500 tokens

Claude lit experiments/mlops.db (binaire illisible), tente d'exporter en CSV 800 lignes, relit le CSV complet pour trouver les 3 dernières runs. 3 500 tokens gaspillés.

✅ Avec MCP SQLite — ~180 tokens

execute_query("SELECT * FROM runs ORDER BY start_time DESC LIMIT 3") → 3 lignes → 180 tokens. Gain : ×20.

MCP Servers essentiels pour MLOps

🗄️

mcp-server-sqlite

Requêtes SQL directes sur mlops.db (runs MLflow, métriques, expériences). Installation : uvx mcp-server-sqlite

📂

mcp-server-filesystem

Accès fichiers précis : liste, lecture partielle, recherche. Plus ciblé que ls + cat enchaînés. Évite de charger des arborescences complètes.

🔎

mcp-server-qdrant

Recherche sémantique dans la base vectorielle. Interroger les paires d'entraînement similaires sans les charger toutes en contexte.

🌐

mcp-server-brave-search

Veille tech (nouveaux modèles, papers) directement depuis CC. Pas de dépendance à un navigateur — résultats directement dans le contexte.

Configuration — niveau global (Green IT : partagée entre projets)

~/.claude/settings.json{
  "mcpServers": {
    "sqlite": {
      "command": "uvx",
      "args": ["mcp-server-sqlite", "--db-path",
               "/Users/wlerouli/Documents/GitHub/mlOps/experiments/mlops.db"]
    },
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem",
               "/Users/wlerouli/Documents/GitHub/mlOps"]
    }
  }
}
💡
Règle MCP Green IT Toute question "quelle est la dernière run avec val_loss < 0.5 ?" doit passer par MCP SQLite. Toute lecture partielle de fichier (lignes 150-200 d'un log) par MCP filesystem. Le LLM n'est pas un système de fichiers.

10. Prompt Cache & Batch API 🌳 Expert

Les mécanismes invisibles qui réduisent les coûts de 50 à 90%

Prompt Cache — économie automatique si CLAUDE.md est stable

Définition — Prompt Cache

Claude met en cache les préfixes de prompts identiques pendant 5 minutes. Si votre CLAUDE.md + contexte système restent stables entre deux échanges, seule la partie nouvelle est traitée. Les tokens en cache sont facturés ~90% moins cher (et consomment proportionnellement moins d'énergie).

Batch API — traitement asynchrone de masse

Définition — Batch API

L'API Batch d'Anthropic permet d'envoyer des milliers de requêtes en une seule fois, traitées de manière asynchrone. Coût : 50% moins cher que l'API standard, avec un délai de traitement de quelques heures. Idéal pour le nettoyage et le scoring de datasets.

📦

Cas d'usage MLOps parfait

Scorer 50 000 paires Python→Java avec Haiku via Batch API : ×50% de réduction de coût, lancé le soir, résultats le matin.

⏱️

Quand l'utiliser

Tâches non-interactives : scoring dataset, évaluation modèle sur test set, génération d'augmentations synthétiques. Pas pour les interactions utilisateur.

Pattern Batch API pour nettoyage de dataset

from anthropic import Anthropic
import json
from pathlib import Path

client = Anthropic()

def score_pairs_batch(pairs_path: Path) -> Path:
    pairs = [json.loads(l) for l in pairs_path.read_text().splitlines()]

    requests = [{
        "custom_id": f"pair-{i}",
        "params": {
            "model": "claude-haiku-4-5-20251001",  # haiku = ×15 moins cher
            "max_tokens": 64,
            "messages": [{"role": "user", "content": f"Score 0-10: {p}"}]
        }
    } for i, p in enumerate(pairs)]

    batch = client.messages.batches.create(requests=requests)
    # Asynchrone — résultats dans quelques heures
    return batch.id

11. Sécurité & Souveraineté 🌳 Expert

Secrets hors settings.json, deny cloud, raw immutable

🔴
Clés AWS en clair dans settings.json = vulnérabilité critique Ce fichier est lisible par tout processus tournant sous votre utilisateur. Utiliser ~/.aws/credentials (chmod 600) + profil nommé dans settings.json.

❌ Secrets dans settings.json

{
  "env": {
    "AWS_ACCESS_KEY_ID": "AKIA...",     // ← DANGER
    "AWS_SECRET_ACCESS_KEY": "abc..."   // ← DANGER
  }
}

✅ Profil AWS standard

# ~/.aws/credentials (chmod 600)
[default]
aws_access_key_id = AKIA...
aws_secret_access_key = abc...

# settings.json — juste la région
{ "env": { "AWS_REGION": "us-east-1" } }

Deny list souveraineté — defense et données classifiées

"deny": [
  "Bash(curl * anthropic*)",    // pas d'appel direct API Anthropic
  "Bash(curl * openai*)",
  "Bash(wget * s3*)",
  "Write(~/mlOps/datalake/raw/**)"  // raw IMMUTABLE après ingestion
]
Définition — Immutabilité du datalake raw

La couche raw/ contient les données sources non transformées. Elle ne doit jamais être modifiée après ingestion — c'est la source de vérité pour rejouer le pipeline. La deny Write dans settings.json en fait une règle technique non-contournable, pas juste une convention.

🌱 Fondamentaux
Qu'est-ce qu'un token, et pourquoi est-il l'unité de mesure Green IT d'un LLM ?
↩ cliquer pour la réponse
Un token ≈ 0,75 mot (4 caractères). C'est l'unité de calcul GPU : chaque token consomme de l'énergie dans un datacenter. 1 fichier Python de 300 lignes ≈ 3 000 tokens. Multiplié par des milliers d'appels/jour, l'impact CO₂ est mesurable et réductible par la configuration.
↩ retourner
Quelle est la différence entre ~/.claude/settings.json et .claude/settings.json ?
↩ cliquer pour la réponse
Global (~/.claude/) : s'applique à tous les projets — modèles, MCP servers, env vars partagées. Projet (.claude/) : versionné dans le repo, contient permissions, hooks, deny list spécifiques. Le projet surcharge le global.
↩ retourner
Pourquoi le CLAUDE.md doit-il être 100% statique (sans timestamps ni IDs dynamiques) ?
↩ cliquer pour la réponse
Le prompt cache d'Anthropic met en cache les préfixes identiques pendant 5 min. Si CLAUDE.md change à chaque session (timestamp, ID de run), le cache est invalidé → 100% des tokens sont refacturés à chaque échange. Un CLAUDE.md statique permet un cache hit rate de 90%+.
↩ retourner
Quel est le rôle de la section "Token Economy" dans CLAUDE.md, et pourquoi est-elle critique ?
↩ cliquer pour la réponse
Elle instruite Claude sur comment utiliser ses propres ressources : quel modèle pour quelle tâche, quand déléguer à un sub-agent Haiku, quand utiliser MCP au lieu de lire un fichier, quand faire /compact. Sans elle, Claude peut consommer ×10 plus de tokens par manque d'instructions explicites.

🌿 Permissions & Hooks
Quelle est la différence entre allowlist et deny list, et laquelle a la priorité ?
↩ cliquer pour la réponse
Allowlist : commandes que CC exécute sans confirmation. Deny list : commandes explicitement interdites même si elles seraient normalement permises. La deny list a la priorité sur l'allowlist — si une commande est dans les deux, elle est bloquée.
↩ retourner
Que signifie Bash(git log*) comme règle d'allowlist ? Qu'autorise-t-elle et qu'interdit-elle ?
↩ cliquer pour la réponse
Autorise toute commande qui commence exactement par git log : git log --oneline -10 ✓, git log --format="%H" ✓.
N'autorise pas : git push ✗, git reset --hard ✗. Le * est un glob suffixe, pas un wildcard global.
↩ retourner
Pourquoi $CLAUDE_TOOL_INPUT ne peut pas être directement utilisé dans un hook echo ?
↩ cliquer pour la réponse
CLAUDE_TOOL_INPUT contient un objet JSON multi-lignes. Un echo direct échoue silencieusement ou produit une entrée vide. Il faut utiliser jq -r '.command // empty' pour extraire le champ texte, et printf '%s | BASH | %s\n' (format en premier argument) pour éviter que les tirets soient interprétés comme options.
↩ retourner
Quelle est la différence entre PreToolUse, PostToolUse et Stop ? Citez un cas d'usage concret pour chacun.
↩ cliquer pour la réponse
PreToolUse : avant l'outil, peut bloquer (code ≠ 0). Ex : valider qu'un fichier à écrire n'est pas dans raw/.
PostToolUse : après l'outil, pour l'audit. Ex : logger la commande Bash dans audit.log.
Stop : fin de réponse Claude. Ex : écrire un marqueur === session end ===.
↩ retourner
🌳 Skills & Agents
Qu'est-ce qu'un skill Claude Code, et en quoi est-il différent d'une entrée CLAUDE.md ?
↩ cliquer pour la réponse
Un skill est un fichier .md dans .claude/skills/, invoqué par /nom. Il contient de la logique d'action : séquence d'étapes, règles spécifiques à une tâche, token economy de la tâche.
CLAUDE.md contient du contexte statique : chemins, stack, règles globales permanentes. Le skill est une macro réutilisable ; CLAUDE.md est le contrat permanent.

Pourquoi créer un sub-agent Haiku pour scorer 5 000 paires plutôt que de laisser le contexte principal le faire ?
↩ cliquer pour la réponse
Trois raisons Green IT : ① Haiku coûte ×15 moins qu'Opus pour cette tâche répétitive. ② Les 5 000 paires restent dans le sub-agent — le contexte principal n'est pas surchargé (sa fenêtre est préservée pour l'orchestration). ③ Avec run_in_background: true, le scoring tourne en parallèle pendant que le principal fait autre chose.

Il doit rester rare car Opus coûte ×15 vs Haiku. Un sous-agent Plan Opus par sprint est raisonnable ; un par tâche courante est du gaspillage.

🌳 MCP & Cache
Pourquoi utiliser MCP SQLite au lieu de lire le fichier mlops.db directement ? Chiffrez le gain.
↩ cliquer pour la réponse
Sans MCP : CC tente de lire le binaire (illisible), exporte un CSV de 800 lignes, le charge entier → ~3 500 tokens.
Avec MCP : execute_query("SELECT * FROM runs ORDER BY start_time DESC LIMIT 3") → 3 lignes → ~180 tokens.
Gain : ×20. Le LLM n'est pas un système de fichiers.
↩ retourner
Le prompt cache d'Anthropic dure combien de temps ? Quelles pratiques le maximisent ?
↩ cliquer pour la réponse
TTL : 5 minutes. Pour maximiser le hit rate : ① CLAUDE.md 100% statique. ② Enchaîner les échanges en moins de 5 min. ③ Utiliser /compact qui résume l'historique sans changer le préfixe stable. Les tokens en cache sont facturés ~90% moins cher.

Où doivent être configurés les MCP servers partagés entre projets, et pourquoi ?
↩ cliquer pour la réponse
Dans ~/.claude/settings.json (global), pas dans chaque projet. Principe Green IT de réutilisation de configuration : un MCP SQLite configuré une fois sert tous les projets qui partagent la même DB. Évite la duplication, garantit la cohérence, réduit le risque d'oubli sur un nouveau projet.

🔐 Sécurité & Souveraineté
Pourquoi ne jamais mettre des clés AWS dans settings.json, même en local ?
↩ cliquer pour la réponse
settings.json est lisible par tout processus tournant sous votre utilisateur (apps, scripts, malwares). Contrairement à ~/.aws/credentials (chmod 600, lu uniquement par le SDK AWS), settings.json n'a pas de permission spéciale. Alternative : ~/.aws/credentials + "AWS_PROFILE": "mon-profil" dans settings.
↩ retourner
Qu'est-ce que l'immutabilité de la couche raw/ du datalake et comment l'imposer techniquement avec CC ?
↩ cliquer pour la réponse
raw/ contient les données sources dans leur état d'origine. Une fois ingérées, elles ne doivent jamais être modifiées — c'est la source de vérité pour rejouer le pipeline. Techniquement : "deny": ["Write(~/mlOps/datalake/raw/**)]" dans .claude/settings.json. La règle est non-contournable par CC, même par erreur.
↩ retourner
Dans un projet defense/classifié, quelles règles deny garantissent la souveraineté des données ?
↩ cliquer pour la réponse
Minimum : "Bash(curl * anthropic*)", "Bash(curl * openai*)", "Bash(wget * s3*)" bloquent les appels cloud sortants. L'inférence en production via mlx_lm.server (local) et les embeddings via Ollama garantissent que aucune donnée ne quitte la machine. CC lui-même peut passer par Bedrock (usage interne dev) sans que les données de prod transitent.
↩ retourner

14. Checklist & Anti-patterns 🌿 Intermédiaire

🌱 Débutant — fondations

  • CLAUDE.md avec contexte, chemins, règles
  • Section Token Economy dans CLAUDE.md
  • "model": "haiku" dans settings global
  • Variables ANTHROPIC_MODEL (Sonnet) + SMALL_FAST (Haiku) + LARGE (Opus)

🌿 Intermédiaire

  • Allowlist minimale pour le travail courant
  • Deny list souveraineté + raw immutable
  • Secrets AWS hors settings.json
  • Hook PostToolUse audit avec jq (pas $CLAUDE_TOOL_INPUT nu)
  • Hook Stop avec echo (pas printf ---)
  • Au moins 3 skills versionnés dans .claude/skills/
  • Mémoire persistante initialisée (MEMORY.md)

🌳 Expert

  • MCP SQLite pour toutes les requêtes métadonnées
  • MCP Filesystem configuré
  • Sub-agents Haiku pour tâches répétitives
  • Batch API pour datasets >500 paires
  • Cache hit rate mesuré et >60%
  • Rapport hebdomadaire sur audit.log
  • Dashboard MLflow avec métriques AI
  • Rotation automatique des clés AWS

🚫 Anti-patterns critiques

Clés secrets dans settings.json

Lisibles par tout process. Utiliser ~/.aws/credentials (chmod 600).

Bash(*) — tout autoriser

Autorise rm -rf /. La friction des prompts est un signal — affiner l'allowlist.

CLAUDE.md avec données dynamiques

Timestamps ou IDs → cache invalidé à chaque session. Zéro économie.

Opus/Sonnet pour tout "par sécurité"

×5 à ×15 le coût. Haiku couvre 60-70% des tâches courantes.

Lire une DB SQLite comme fichier

Binaire illisible → CSV 800 lignes → 3 500 tokens. MCP SQLite : 180 tokens.

Sessions sans /compact

Après 30 échanges, le contexte est redondant. /compact libère la fenêtre.
