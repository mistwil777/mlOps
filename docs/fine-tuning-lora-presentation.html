04
L'architecture en 3 composants

Modèle · Adapters · RAG :
qui fait quoi ?

Trois composants complémentaires. Chacun a un rôle précis. Ensemble, ils couvrent tous les besoins.

🧠 Modèle de base
Le cerveau. Intelligence générale — raisonnement, langage, logique. Fourni par la communauté open-source (Mistral, Qwen). Ce n'est pas notre IP.
Entraîné 1 seule fois · stable
🔌 Adapters LoRA
Les spécialisations. Petits modules (~40 Mo) entraînés sur vos données métier. Chargés dynamiquement selon la tâche. C'est notre IP — l'adapter Capgemini.
Re-entraînable · mise à jour rapide
📚 RAG — La bibliothèque
Avant de répondre, le modèle consulte une base de documents à jour (vos manuels, réglementations). Il lit les pages pertinentes, puis répond en citant ses sources.
Documents mis à jour sans re-entraîner
05
RAG expliqué

Le RAG :
l'assistant qui lit avant de parler

Sans RAG, le modèle répond uniquement de sa mémoire d'entraînement. Avec RAG, il consulte en temps réel vos documents — comme un expert qui vérifie son manuel avant d'agir.

💬
Question
"Quelle est la procédure pour le code E-4412 sur le CFM56 ?"
→
🔍
Recherche RAG
Cherche dans les manuels les passages sur E-4412 et CFM56
→
📖
Résultats
TM-2J-CFM56 p.247 · Service Bulletin SB-CFM56-72-0445
→
🧠
Modèle + Adapter
Lit les extraits · raisonne avec son expertise fine-tunée
→
✅
Réponse précise
Procédure étape par étape, sources citées, conformité vérifiée

📌 Important : le modèle fine-tuné est autonome — il fonctionne sans RAG une fois embarqué. Le RAG est un enrichissement optionnel : quand les documents clients sont disponibles, il améliore la précision. Quand ils ne le sont pas, le savoir métier intégré lors du fine-tuning suffit à répondre.

08
Risques & Sécurité

Data poisoning et injections :
ce qui est vrai, ce qui ne l'est pas

Comprendre exactement ce qu'une donnée malveillante peut — et ne peut pas — faire.

❌ Idée reçue
🦠
"Une injection dans les données peut pirater le modèle à distance"
✗
Un modèle de langage n'est pas un logiciel exécutable — c'est une collection de nombres (poids). Il ne peut pas être "pris en main" à distance.
✗
Le fine-tuning ne connecte pas le modèle à internet. Il n'y a aucun canal de communication entrant post-entraînement.
✗
Un modèle ne peut pas "appeler chez lui" une fois déployé hors-ligne.
✅ La réalité du risque
⚠️
"Le vrai risque : des données corrompues dégradent les réponses"
!
Data poisoning : introduire des exemples faux biaise le modèle vers des réponses incorrectes (ex: des procédures erronées volontairement).
!
Backdoor : dans des cas très sophistiqués, une donnée peut amener le modèle à se comporter différemment face à un "mot-clé" spécifique.
!
Ces risques se traitent en amont, avant l'entraînement, par le filtrage des données.

12
Amélioration continue

D'où viennent les nouvelles données ?
Le cycle de réentraînement

Le modèle s'améliore à chaque cycle. Chaque usage terrain produit des données qui alimentent le réentraînement suivant — sans jamais sortir du périmètre client.

📥 Sources de nouvelles données
🖥️
Outputs du système en production
La source principale — ce que le modèle a produit
Chaque réponse générée en prod est un candidat : question posée + réponse produite + feedback opérateur (validé / corrigé / rejeté). C'est la paire instruction→output qui alimente le fine-tuning.
✍️
Corrections des experts terrain
La source la plus précieuse
Quand un technicien corrige ou améliore une réponse du modèle, cette correction devient une paire de réentraînement à très haute valeur — elle encode le savoir tacite des experts.
📄
Nouveaux documents clients
Manuels, bulletins, mises à jour réglementaires
De nouveaux manuels TM, bulletins service ou textes réglementaires sont ingérés. Ils vont d'abord dans le RAG (disponibles immédiatement), puis on en extrait des paires pour le réentraînement suivant.
🌐
Web scraping supervisé
Uniquement pour données non-classifiées
Pour les projets sans contrainte Secret Défense : docs publics, forums techniques, normes ouvertes. Filtrés et scorés avant ingestion — cf. slide précédente sur la qualité données.
🔄 Pipeline de réentraînement
1
Collecte & ingestion
Outputs prod, corrections experts, nouveaux docs → datalake/raw/ (immuable)
2
Nettoyage & scoring qualité
Déduplication, score BLEU/ROUGE, rejet des paires sous seuil → datalake/processed/
3
Injection RAG (immédiate)
Les nouveaux documents sont indexés dans Qdrant — disponibles pour le modèle en production dès maintenant, sans réentraîner
4
Extraction de paires d'entraînement
Les documents RAG + corrections terrain génèrent des paires instruction → output pour le fine-tuning → datalake/fine-tuning-ready/
5
Réentraînement LoRA
Nouvel adapter entraîné sur les données cumulées — évaluation obligatoire avant de remplacer le précédent
6
Déploiement du nouvel adapter
Livraison client : mise à jour du bundle via support physique sécurisé → le modèle est plus précis, sans toucher au modèle de base
⚡

RAG vs Réentraînement — deux temporalités différentes. Le RAG enrichit le modèle immédiatement (nouveaux docs disponibles en minutes). Le réentraînement intègre le savoir en profondeur (cycles de semaines). Les deux sont complémentaires — le RAG ne remplace pas un réentraînement, il le prépare.
