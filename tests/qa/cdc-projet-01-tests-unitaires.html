Contexte client

La Banque Régionale Atlantis (BRA) est une banque de taille intermédiaire (~1 200 collaborateurs) qui maintient un système de gestion de comptes développé en interne depuis 2009. La base de code principale est en Java 17, organisée en modules Maven, avec un framework de tests maison construit au-dessus de JUnit 5.

L'équipe de développement compte 18 développeurs. Chaque semaine, 30 à 40 nouvelles méthodes sont écrites ou modifiées. La politique qualité impose une couverture de tests minimale de 80 % par module. En pratique, l'écriture des tests représente environ 2h par développeur par jour — du temps consacré à du code répétitif et prévisible.

BRA a une contrainte forte de souveraineté : aucun code source ne peut transiter par un service cloud externe (concurrence, secret bancaire, RGPD). Un modèle local est obligatoire.

Stack technique

Langage et build

  • Java 17 (LTS)
  • Maven 3.9 (modules multi-projets)
  • Spring Boot 3.2 (couche service)
  • Hibernate 6 (ORM)

Framework de tests

  • JUnit 5 avec runner interne BraTestRunner
  • Mockito 5 pour les dépendances
  • Fixture maison @BraTest (annotation custom)
  • AssertJ pour les assertions

Conventions de nommage

  • Méthode : should_[résultat]_when_[condition]
  • Classe : [ClasseCible]Test
  • Package : com.bra.[module].test

Patterns récurrents

  • Setup via @BeforeEach avec BraTestContext
  • Mocks déclarés via @BraMock
  • Audit log systématique : BraAudit.verify()
  • Transactions wrap : withTransaction(db, () -> ...)
Problème actuel
Sans modèle spécialisé

Un développeur demande à un LLM générique d'écrire un test pour TransferService.execute().

@Test
void testTransfer() {
    TransferService svc = new TransferService();
    boolean result = svc.execute(100, "A1", "A2");
    assertTrue(result);
}

✗ Pas d'annotation @BraTest
✗ Pas de BraTestContext
✗ Pas de mock @BraMock
✗ Convention de nommage incorrecte
✗ Pas d'audit verify
✗ Ne compile pas — dépendances manquantes

Avec modèle fine-tuné BRA
package com.bra.transfer.test;

import com.bra.test.BraTest;
import com.bra.test.BraTestContext;
import com.bra.test.BraMock;
import com.bra.audit.BraAudit;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;
import static org.assertj.core.api.Assertions.*;

@BraTest
class TransferServiceTest {

    @BraMock AccountRepository accountRepo;
    @BraMock AuditLogger auditLogger;
    private TransferService svc;

    @BeforeEach
    void setUp() {
        BraTestContext.init(accountRepo, auditLogger);
        svc = new TransferService(accountRepo, auditLogger);
    }

    @Test
    void should_transfer_funds_when_accounts_are_valid() {
        withTransaction(BraTestContext.db(), () -> {
            Account src = BraTestContext.account("A1", 500.0);
            Account dst = BraTestContext.account("A2", 0.0);
            svc.execute(100.0, src, dst);
            assertThat(dst.getBalance()).isEqualTo(100.0);
            BraAudit.verify(auditLogger, "TRANSFER", src.getId());
        });
    }
}

✓ Toutes les conventions respectées
✓ Compile et passe la CI directement

Objectif
🎯

Entraîner Qwen2.5-Coder-7B-Instruct à générer des tests JUnit 5 conformes aux conventions BRA à partir d'une signature de méthode Java. Le modèle doit produire un test compilable et valide sans aucune correction manuelle dans 80 % des cas (pass rate cible).

Structure des paires d'entraînement

Format JSONL

{
  "prompt": "Écris un test JUnit 5 pour la méthode Java suivante :\n\n```java\n// Package: com.bra.payment\n// Classe: PaymentService\npublic PaymentResult process(Payment payment, Account account) {\n    // Valide le solde, débite le compte, enregistre l'audit\n}\n```\nUtilise les conventions BRA : @BraTest, BraTestContext, @BraMock, AssertJ, BraAudit.verify().",
  "completion": "package com.bra.payment.test;\n\nimport com.bra.test.BraTest;\n// ... [test complet conforme aux conventions]"
}
📐

Prompt : signature de méthode + classe + package + instructions conventions BRA. ~150–250 tokens.

✍️

Completion : test Java complet, compilable, avec toutes les annotations et patterns BRA. ~300–600 tokens.

Une paire est rejetée si un seul critère bloquant n'est pas satisfait. Les critères "Important" contribuent au score de qualité (1–5) mais ne bloquent pas.
